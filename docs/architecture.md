# Архитектура Nodehome

## Публичная часть

Публичные страницы генерируются в site/ из источников в content/. Каждая статья, категория, направление, группа и подтема получает отдельный HTML-файл. Поисковый робот получает заголовок, описание, хлебные крошки и canonical непосредственно в HTML.

В браузере нет SPA-роутера и загрузки контента по #. Файл assets/site.js содержит расчёты калькуляторов, фильтрацию локального списка на странице поиска и закрытие мобильного меню по Escape или клику вне меню. Главное меню формируется из направлений и групп в content/sections.json: пункты направлений ведут на собственные страницы, а выпадающий список содержит только тематические группы. Страницы направлений ведут на страницы групп, страницы групп — на страницы подтем.

## Источник контента

- content/site.json — название, порядок пунктов меню и блоки главной страницы.
- content/sections.json — пять направлений, тематические группы и подтемы со стабильными идентификаторами.
- content/categories.json — существующие категории, их описания, принадлежность к группе и список статей.
- content/articles.json — slug, основная категория, необязательная подтема, метаданные, текст, вопросы, источники и адреса изображений.
- assets/images/ — изображения сайта; генератор копирует их в site/assets/images/.

scripts/build.mjs превращает эти данные в готовые страницы, sitemap.xml и robots.txt. Направления открываются по адресам вида /construction/; группы и подтемы вложены в соответствующее направление. Существующие страницы категорий и статей сохраняют прежние адреса. Для прежних URL направлений и групп генерируются страницы перенаправления с canonical на новые адреса.

В sitemap попадают только страницы, связанные с опубликованными материалами. Страницы групп и подтем без публикаций остаются доступны из каталога, но получают noindex,follow и не добавляются в карту сайта.

## Подготовка к админ-панели

Админ-панель можно подключить отдельным серверным слоем, сохранив текущие адреса и публичную разметку:

1. Авторизация и роли редактора/администратора выполняются на сервере. Секреты и права доступа не хранятся в клиентском JavaScript.
2. API для чтения и редактирования материалов работает с теми же полями, что и JSON-источники: slug, title, description, categoryIds, image, imageAlt, minutes, sections, faqs, sources, status. Раздел статьи может содержать абзацы, списки, иллюстрацию с alt и подписью, внутренние ссылки и callout.
3. Черновики не попадают в публичную сборку. Публикация запускает генератор, обновляет HTML, canonical и sitemap.xml.
4. Загрузка изображений проходит через серверную проверку типа и размера, затем возвращает относительный путь из assets/images/.
5. При смене slug сервер сохраняет перенаправление со старого URL, чтобы не терять внешние ссылки и поисковые сигналы.
6. Для редактирования нужна серверная база данных или CMS. JSON-файлы сейчас служат понятным форматом обмена и не заменяют авторизацию, совместное редактирование и журнал изменений.

Публичная часть уже отделена от источника данных и генератора. Это оставляет будущей админке стабильный формат контента и не связывает её с конкретной CMS.
